# План Unit-тестов: Local React AI

## Цель
Написать unit-тесты для бизнес-логики проекта. Компоненты React и API-зависимый код тестируются через моки.

## Выбор фреймворка
- **Jest + Vite** (через `@vitejs/plugin-react` + `vite-jest`)
- **Vitest** — альтернатива, лучше интегрируется с Vite, но Jest стабильнее для React

Рекомендация: **Vitest** (нативная интеграция с Vite, нет необходимости в трансформации).

## Что тестировать

### 1. `aiService.js` — моки Wllama
| Тест | Описание |
|------|----------|
| `initWllama()` | Возвращает singleton, вызывается один раз |
| `loadModelFromFile()` — валидный GGUF | Прогресс: 5 → 20 → 100, вызывает `wllama.loadModel` |
| `loadModelFromFile()` — неверный магический номер | Бросает ошибку, прогресс сбрасывается на 0 |
| `loadModelFromFile()` — `onProgress` = null | Не бросает ошибок |
| `unloadModel()` | Сбрасывает `wllamaInstance` и `chatHistory` |
| `addMessageToHistory()` + `getChatHistory()` | Добавляет/возвращает копию массива |

### 2. `fileStorage.js` — моки IndexedDB + File System Access API
| Тест | Описание |
|------|----------|
| `getDB()` | Открывает БД `LocalReactAIVault` v1 с store `FileHandles` |
| `getSavedFileHandle()` — сохранён | Возвращает handle из БД |
| `getSavedFileHandle()` — не сохранён | Возвращает `null` |
| `verifyPermission()` — granted | Возвращает `true` |

### 3. Компоненты React — моки props
| Компонент | Тест |
|-----------|------|
| `WelcomeScreen` | Рендерит 2 кнопки, отображает error если передан |
| `LoadingScreen` | Прогресс-бар имеет `width: X%`, текст `X%` |
| `AccessScreen` | Рендит имя файла, 3 кнопки |
| `ChatWorkspace` | Рендерит input, кнопка submit disabled если `isGenerating` |

## Моки

### Wllama mock
```js
const mockWllama = {
  setCompat: jest.fn(),
  loadModel: jest.fn().mockResolvedValue(undefined),
  isModelLoaded: jest.fn().mockReturnValue(true),
  getLoadedContextInfo: jest.fn().mockReturnValue({ n_ctx: 4096, n_layer: 24, n_vocab: 151936, n_embd: 2048, metadata: {} }),
  createChatCompletion: jest.fn().mockResolvedValue(createAsyncIterator([{ choices: [{ delta: { content: 'test' } }] }])),
  createCompletion: jest.fn().mockResolvedValue(createAsyncIterator([{ choices: [{ text: 'result' }] }])),
  exit: jest.fn().mockResolvedValue(undefined),

jest.mock('@wllama/wllama', () => ({ Wllama: jest.fn().mockImplementation(() => mockWllama) }));
```

## Порядок реализации

1. Установить зависимости: `npm i -D vitest @testing-library/react @testing-library/jest-dom jsdom`
2. Добавить в `package.json`: `"test": "vitest"` и `"test:run": "vitest run"`
3. Создать `vite.config.test.js` или настроить `vitest.config.js`
4. Создать `__tests__/setup.js` с глобальными моками
5. Написать `aiService.test.js`
6. Написать `fileStorage.test.js`
7. Написать `components.test.jsx`

## Ревью после реализации
- [ ] Все тесты проходят (`npm run test:run`)
- [ ] Моки покрывают все ветки ошибок
